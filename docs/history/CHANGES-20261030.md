# CARD-WEB：网页端新窗口绑定失败 + 目标文档数量为 0（2026-11-01 08:0x）

## 根因（实测出来的，不是推断）

一条实测把两个现象并成同一个原因：**窗口不在前台时，Chrome / Electron 页面文档的
UIA URL 是空串。**

```
Gemini 窗口后台:  DocumentControl name=''             value=''          ← 读不到
Gemini 窗口前台:  DocumentControl name='Google Gemini' value='https://gemini.google.com/app'
OpenCode 后台:    DocumentControl name=''             value=''
OpenCode 前台:    DocumentControl name='OpenCode'      value='oc://renderer/index.html'
```

`qi/ui.py` 原来的 `documents()` 用 `if pattern and pattern.Value:` 过滤，空串被当成
"这个窗口没有文档"。于是：

1. **网页端 `no_window`**：`_spawn()` 用 `SW_SHOWMINNOACTIVE` 开窗、`place()` 带
   `SWP_NOACTIVATE`，新窗口**从头到尾没进过前台**。`await_page()` 靠 `ui.documents()`
   读 URL 判断"是不是目标页"，永远读不到 → 12 秒轮询全假 → `ensure_site` 返回 None
   → `stage=no_window`，窗口还留在桌面上（06:0x 那 3 个就是这么来的）。
2. **`opencode_use --new` / `workbuddy_use --list` 报「目标文档数量为 0」**：同一个过滤。
   opencode 在后台时 URL 是空串 → 0 个候选 → 直接抛错。
3. 用户报的「WorkBuddy 空闲后读不到文档、重启 WorkBuddy 才恢复」：同一类问题（窗口不在
   前台时 URL 读不到），再叠加 UIA 会话放久了失效。

## 关键行为（验收按这个看）

**扩展 ID 是算出来的，不是分配的。** `key` 是 RSA-2048 公钥的 base64(SPKI DER)，
Chrome 取 `SHA256(DER)` 前 16 字节，每个 hex 位映射成 a–p：

```
SHA256(294 字节 DER)[:32] → 每字符 0-9a-f 换成 a-p → odjanlclocbikpjlkcfepnfbcejlapkd
```

单测直接从 manifest 的 `key` 反算一遍，和后端 `allowed_extension_id` 比对，两边不一致就红。

**Origin 三种情形**（合并三家会审的分歧：Gemini 说扩展 GET 可能不带 Origin，ChatGPT 要求拒绝缺失 Origin）：

| 请求 | 配了 allowed_extension_id（真机） | 没配（只有临时 root 的用例） |
| --- | --- | --- |
| `Origin: chrome-extension://<本扩展>` | 放行（仍要 Bearer） | 放行 |
| `Origin: chrome-extension://<别的 ID>` | **403 bad_origin** | 放行（前缀规则） |
| `Origin: https://...` / `null` / 带多余 `/` | **403** | **403** |
| 无 Origin | 放行，但必须带 Bearer | 同左 |

**token 不进浏览器任何可读的地方**：只进 `chrome.storage.local`，启动先
`setAccessLevel({accessLevel:"TRUSTED_CONTEXTS"})`；保存后立刻清空输入框；不写日志、不发 sync、
不注入 content script（manifest 里没有 `content_scripts`，代码里没有 `chrome.scripting`）。

**任务生命周期**：`/ask` 202 → `job_id` 存 `storage.local`（带 `created_at`）→ 每 3 秒 `/jobs/<id>`；
空闲时降到 20 秒；24 小时前的记录自动清掉；关掉侧栏再打开会先补一轮再进轮询。
