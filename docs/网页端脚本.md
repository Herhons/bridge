# 网页端 `_use` 脚本（2026-10-29）

四个网页端共用 `src/qi/flow.py` 里同一份流程，每个脚本只写本端配置。
拆分方式沿用 v0.0.8：`_choose` 管选择、`_use` 管提问。**本轮只做了 `_use`。**

```
src/qi/screen.py      截屏 / 找图 / 点击 / 输入 / 剪贴板 / 提前台 / 等静止
src/qi/flow.py        唯一一份「提问→收回答」流程
src/scripts/deepseek_use.py
src/scripts/grok_use.py
src/scripts/chatgpt_use.py
src/scripts/gemini_use.py
tools/snip.py         截模板
```

## 八个脚本

| 端 | 选择 | 提问 |
|---|---|---|
| deepseek | `deepseek_choose.py` 深度思考 / 智能搜索 | `deepseek_use.py` |
| grok | `grok_choose.py` fast / expert / auto / build | `grok_use.py` |
| chatgpt | `chatgpt_choose.py` 思考强度 instant / mid / （high） | `chatgpt_use.py` |
| gemini | `gemini_choose.py` flash_lite / flash / pro / argon | `gemini_use.py` |

共用：`src/qi/screen.py`（找图/点击/输入）、`src/qi/flow.py`（提问流程）、`src/qi/choose.py`（菜单选择流程）。

## `_choose` 怎么工作（没有 OCR 的限制）

读不出任意文字，所以**每个档位用两张图代表**：

- `<prefix>item_<key>.png`：菜单里那一行的样子（点它）
- `<prefix>chip_<key>.png`：选中后芯片的样子（读它）

`--list` = 匹配芯片图；`--model X` = 开菜单 → 点 item 图 → 用 chip 图复核。
没有 chip 图的档位"能设不能读"。

三条实测坑：

1. **hover 会改外观**。芯片被鼠标压着时会变成另一种底色（有胶囊背景），
   和静止时截的模板对不上。所以每次读之前都先 `Esc` + 把鼠标移开（`_calm()`）。
2. **芯片位置会随名字长短变**。Gemini 用"点当前芯片"开菜单（`open_by_chip`）；
   ChatGPT 用**右下角橙色语音键**当基准（芯片 = 键中心左 70、上 3）。
3. **chatgpt 的强度滑杆单击没用**，必须按住拖（已加 `Screen.drag`）。
   但实测拖到最右也只停在「中」——`高` 在当前模型下不可达，不是脚本问题。

## 关于 `--tab`

脚本只操作**自己那个标签页**。当前激活的是别的站时，先按 `--tab N` 切过去（从左边数）：

```bash
$PY src/scripts/grok_choose.py --list --tab 1
$PY src/scripts/chatgpt_use.py "问题" --tab 2
```

## 维度对照：v0.0.8 能选什么 vs v0.0.9 现在能选什么

| grok 网页 | 4 项（第 5 项 Heavy 需订阅） | 无（型号即模式） | — | — |
| gemini 网页 | 对话 4 项 / 任务 2 项 | 对话 3 档 / 任务无 | 对话 / 任务 | — |
| chatgpt 网页 | 聊天 2 项 / 工作 9 项 | 聊天 3 档 / 工作 5 档 | 聊天 / 工作 | — |

v0.0.9 现状（**只做了网页 4 端，桌面 4 端没做**）：

| 端 | 模型 | 强度 | 写入器模式 |
|---|---|---|---|
| deepseek | — | ✅ 深度思考 / 智能搜索 | — |
| grok | ✅ fast / expert / auto / build | — | — |
| gemini | ✅ flash_lite / flash / pro / argon | ❌ 思考等级没做 | ❌ 只截到两张图，切换没验 |
| chatgpt | ❌ 模型选择没做（在「中 ›」子菜单里） | ⚠️ instant / mid 可用，high 不可达 | ❌ 没做 |

**明确的缺口**（按优先级）：

1. **chatgpt 模型选择**：现在只做了强度。模型在弹层里「中 ›」那层子菜单，要多一层交互。
2. **写入器模式**（chatgpt 聊天/工作、gemini 对话/任务）：换模式会换掉整套模型列表，
   所以它必须在选模型之前。gemini 的两个按钮只在新对话页出现，已截到
   `gem_writer_dialog_on` / `gem_writer_task_off`，但**另一方向的两种态还没截到**——
   当前窗口被改成 1404×920 后，点「任务」两次都没生效，位置还在随滚动变化。
3. **gemini 思考等级**：对话模式下的子菜单，没做。
4. 桌面 4 端（codex / dsh / workbuddy / opencode）：完全没做。

### 为什么写入器模式卡住了（2026-10-29 实测）

试过两种截法，都不成立：

1. **截胶囊本身**：选中态是白胶囊、页面也是白的，对比度太低，模板几乎是一片白，
   全屏到处都能匹配。作废。
2. **截文字**：「聊天 / 工作」只有两个字，四种态（聊天选中 / 聊天未选 / 工作选中 / 工作未选）
   互相都能匹配到 **1.000**——字重和灰度的差别太小，`TM_CCOEFF_NORMED` 抹平了。
   作废。

这两组图我已经从资源库删掉，不留在里面骗人。

**可行的替代方案**（v0.0.8 用的就是这个思路）：不认按钮，改认**输入框占位文案**——
聊天模式是「询问 ChatGPT」，工作模式是另一句。整句文本长、区分度高，比两个字的标签稳得多。
同样的办法可以用于 gemini 的「对话 / 任务」（占位分别是「询问 Gemini」和任务模式那句）。

### 顺带修好的：侧栏收起时的「新对话」

实测 ChatGPT 侧栏收起后，「新聊天」那条 352px 的按钮**消失**，只剩一个铅笔图标。
现在 `newchat` 支持多个候选，按顺序找：

```
newchat=("gpt_newchat", "gpt_newchat_icon")   # 展开=整条，收起=铅笔图标
```

还没走到候选就点侧栏开关展开再找一遍。ChatGPT 这条已实测（`via=gpt_newchat_icon`）。


## 各端实测结论（都是踩出来的）

| 端 | 输入框锚点 | 发送键怎么判 | 动作条 | 坑 |
|---|---|---|---|---|
| deepseek | 麦克风图标 `ds_composer`，偏移 (-300,-65) | **颜色**：B-R>100 才可点 | `ds_actions` 6 连排 | 深蓝/浅蓝模板分都是 1.000 |
| grok | 「+」`grok_composer`，偏移 (250,-27) | **出现即用** | `grok_actions` 6 连排 | 占位文案轮播，不能当锚点 |
| chatgpt | 「+」`gpt_composer`，偏移 (240,-5) | **出现即用**（橙底换图标） | `gpt_actions` 6 连排 | 窗口标题会变成会话名 |
| gemini | 「+」`gem_composer`，偏移 (200,0) | **出现即用**（蓝色圆） | `gem_actions` 5 连排 | **复制在第 4 个**，不在排首 |

三条通用规律：

1. **发送键往往"空箱不出现"**：grok/chatgpt/gemini 空输入时右侧是语音键，
   输入后才换成发送键。所以"发送键出现"本身就是"文字写进去了"的判据。
2. **chatgpt 的橙色按钮换图标不换色**：波形→箭头，颜色一样，只能靠模板形状区分。
3. **标题会变成会话名**：ChatGPT 开个会话后窗口标题成了「回复收到」。
   所以 `bring_to_front` 对网页端一律按 **"Google Chrome" + 中心在副屏** 找，
   不按站点名找。

## 复制键：整排定位（用户提的判据）

回答下面的动作条是整排图标，全屏唯一；提问气泡上的复制键是孤立的。
所以先在整排的 bbox 内找复制键；整排找不到才退回"单图标 + 右侧有同伴"。

多轮会话里有多排，取**最靠下**那排＝最新回答。

## 生成结束的判据

1. 有 `ds_stop` 的端：停止键出现→消失。
2. 没有的端：**等画面静止**（连续 2 帧、间隔 0.7s 几乎无变化）。
   只比**输入框所在显示器**——主屏在放视频，整屏比永远不静。

## 边界

- 只在**本机副屏、当前缩放、当前主题**（gemini 深色，其余浅色）下验过。换主题/缩放要重截模板。
- 长回答把动作条顶出视口时会失败（报 `copy_not_found`），没有滚动兜底。
- `_choose`（选模型/档位）三端都还没做。
