四个网页端共用 `src/qi/flow.py` 里同一份流程，每个脚本只写本端配置。
拆分方式沿用 v0.0.8：`_choose` 管选择、`_use` 管提问。**本轮只做了 `_use`。**

## `_choose` 怎么工作（没有 OCR 的限制）

读不出任意文字，所以**每个档位用两张图代表**：

- `<prefix>item_<key>.png`：菜单里那一行的样子（点它）
- `<prefix>chip_<key>.png`：选中后芯片的样子（读它）

`--list` = 匹配芯片图；`--model X` = 开菜单 → 点 item 图 → 用 chip 图复核。
没有 chip 图的档位"能设不能读"。

三条实测坑：

1. **hover 会改外观**。芯片被鼠标压着时会变成另一种底色（有胶囊背景），
   和静止时截的模板对不上。所以每次读之前都先 `Esc` + 把鼠标移开（`_calm()`）。
2. **芯片位置会随名字长短变**。Gemini 用"点当前芯片"开菜单（`open_by_chip`）；
   ChatGPT 用**右下角橙色语音键**当基准（芯片 = 键中心左 70、上 3）。
3. **chatgpt 的强度滑杆单击没用，必须按住拖**（`Screen.drag`）。
   拖动会「打折」：拖 60px 只走 34px（网页对 mousemove 有节流），
   所以拖完必须读回实际位置反复逼近，不能指望一次到位。

## ChatGPT 的弹层是**两层**（2026-10-29 用户指出，实测确认）

```
点芯片（UIA 的「选择 ChatGPT 模型」按钮）
   └─> effort 层：一条滑杆 + 一项「选择模型」
           点「选择模型」
               └─> models 层：模型列表
           选完模型
               └─> 自动退回 effort 层   ← 这里是调强度的位置
拖滑杆调档位 -> Esc 关闭 -> 强度才生效（芯片这时才从占位文字变成「GPT-6 Astra 高」）
```

旧版把两层当成一层：选完模型就按 Esc 把整个弹层收掉，等于把第二步吃掉了。
表现就是「选完 `default` 之后老断」「强度调不了」。现在的状态机是：

| 状态 | 判据 |
|---|---|
| `models` | 找到勾，或 ≥2 个模型项模板命中 |
| `effort` | `_slider()` 找到滑杆（橙色块落在橙钮下方 60~140px、且在轨道 x 内） |
| `closed` | 都不是 |

## ChatGPT 的位置（都是量出来的）

| 东西 | 值 |
|---|---|
| 打开弹层 | **点芯片**（UIA `选择 ChatGPT 模型` 按钮的真实矩形中心）。不再用 `Ctrl+Shift+M`——它会被 Chrome 截成个人资料菜单（CARD-06c 第 4 条） |
| 点前检查 | 唯一性（正好 1 个）→ 不落在听写/语音/发送按钮里 → 离橙钮 ≥60px；点后复核弹层真的出现 |
| 滑杆轨道 | 窗口内 x=954..1239，滑块圆心 y = 橙钮 y + 94 |
| 滑块圆心 | = 橙色块右端 − 16。最低档时橙色只有滑块本身，这条仍成立 |
| 五档 | 981=轻度，1041=中，1102=高，1163=极高，1223=Max（等分） |
| 入口行（进列表） | 弹层里的「选择模型」（MenuItemControl，可 Invoke）；读不到才回落"滑块圆心上方文字行" |

## ChatGPT 的模型选择（聊天 2 项 / 工作 9 项）

`chatgpt_choose.py --model <名字>`，模型列表**按写入器模式分开**：

| 模式 | 可选项 | 状态 |
|---|---|---|
| chat | gpt6 / gpt56 | ✅ 往返验过 |
| work | default / gpt61_sol / gpt61_terra / gpt6_astra / gpt6_sol / gpt6_luna / gpt56_sol / gpt56_terra / gpt56_luna | 9 项全 ✅（`gpt56_luna` 要滚动，已支持） |

先 `--writer work` 再 `--model ...`；模型名不属于当前模式会直接报 `bad_arg` 并列出可选值。

**读当前模型**用列表项行尾的勾（`gpt_check`），不用芯片文字——模型名不显示在芯片上。
「默认（推荐模型集）」那一行是两行文字、比别的行高，模板时灵时不灵，
所以留了兜底：勾在所有可读项**上方**时，选中的就是第一行「默认」。

**一次切换只开两次菜单**（聚焦 1 下 + 入口行 1 下 + 目标项 1 下 + 复核 1 下 = 4 下）。
旧版读一次就开关一遍菜单，一次 `--model` 点 7 下，撞穿 8 下的预算，
超了以后每一下都被拒，表现为「第一个失败、后面全报打不开」。

## ChatGPT 列表滚动（`gpt56_luna` 等第 9 项）

工作模式 9 项，一屏只放得下 8 项（各项间距 36px），第 9 项 `gpt56_luna` 要往下滚 1 格。
滚到底后再滚不会翻页，位置不变。

三条必须同时满足，缺一条就废：

1. **鼠标要先移到列表上**。滚轮事件发给鼠标当前位置下面的窗口，放窗口中心没用
   （那是页面正中，实测怎么滚都没反应）。用「已可见的某一项的坐标」当落点。
2. **搜索范围要限制在列表内**。芯片上也会出现模型名——选中 GPT-5.6 Luna 后芯片就写着
   「GPT-5.6 Luna 高」，`gpt56_luna` 模板在芯片上匹到 **0.928**、过了 0.85 阈值，
   而且比列表项还先撞上，点下去点到列表外面。
   做法：把匹配到的项按 y 排序、按「相邻间距 ≤60px」分组，取最长那组 ±40px
   （列表项间距 36，芯片离列表 70px 以上会单独成组被丢掉）。
3. **复核要上下都找一遍**。列表默认停在顶部，选中项在底部时勾在视口外，必然读成
   `unknown`（实测模型其实切成功了，芯片都变了，只是复核读不到）；
   反过来为了找靠下的模型滚到底，顶部「默认」那一行的勾又会滚出去。
   所以 `_pick_model` 给三次机会：原位 → 滚到顶 → 滚到底。

`Screen.scroll(notches, at=)` 是新加的：正数向上、负数向下，一格 = 120。

## 强度（effort）

`chatgpt_choose.py --effort <档位>`，两个模式的档位**不一样**：

| 模式 | 档数 | 档位 | 滑块圆心（窗口内 x） |
|---|---|---|---|
| work | 5 | 轻度 / 中 / 高 / 极高 / Max | 988 / 1046 / 1097 / 1154 / 1211 |
| chat | 3 | 即时 / 中 / 高 | 1013 / 1115 / 1217 |

**用键盘方向键，不用拖。** 拖拽实测不可靠：

- 拖 -52px 实际走 -82px（过冲）；拖 60px 只走 34px
- **连续拖同一个控件从第二次开始就不动了**
- 一次只能落在两档中间（实测 1072，离两边各 30px），UI 其实没定下来

方向键是精确的：点一下滑块拿焦点 → 按左键到底归零 → 按右键走 N 次。每按一次正好一档。

判断当前档位**以芯片文字为准**（CARD-06b 第 10 条改的）：弹层关着时芯片上写的就是档位词
（工作模式画面上是「GPT-6.1 Sol 高」、聊天模式只有「高」）。弹层开着时芯片变成占位
（「选择推理强度」/「思考强度」），这时读滑杆旁边的可访问值 `高，第 3 项，共 3 项。`。
**滑杆几何位置只作诊断**，不用来判读回——06b r1 的"假读数"就是拿位置推出来的。
注意：**工作模式的芯片按钮在 UIA 里没有子文本**（2026-11-02 实测，按钮名只有
「选择 ChatGPT 模型」），所以那一档读芯片会读空、回落到滑杆几何；聊天模式的「高」
是能直接读到的。

滑杆定位（`_slider`）不能用橙色判据——**滑块停在最低档时整条滑杆是灰的，
一点橙色都没有**，弹层开着也会被判成没开。现在找的是轨道本身：
橙钮下方 40~170px 里一条长 170~340px、宽度稳定的横条，再按两种情况定滑块：

- 轨道上有橙色 → 圆心 = 橙色最右端 − 16（这条从最低档以外全部成立，包括填满的 Max）
- 轨道全灰 → 橙色填充为 0 = 停在最低档 → 圆心 = tx0 + 33

顺序：`--model` 和 `--effort` 一起传时，先选模型再调强度——
选完模型会自动退回强度层，正好是调强度的位置；反过来要先重开一次弹层。

### 踩过的坑（都是实测）

| 现象 | 真因 |
|---|---|
| 弹层开着却说没开 | 用橙色判据，最低档没有橙色 |
| 候选轨道里只有下方阴影 | 滑块把轨道切成两段，最长段 130px 不到 170 的下限；改看「首尾跨度 + 像素占比」 |
| 轨道高度算成 15 行 | 按连续行分组，轨道被切成 2/3/7 三小段；改看「宽度接近最宽行」（轨道等宽 268~270，阴影从 260 收到 208） |
| 点入口行把弹层点没了 | 扫描范围 96px 扫到了芯片（在滑块上方 78px 那一行）；收到 60px 以内 |
| 点滑块被拦「落在录音/发送键上」 | 橙色守卫半径 100，而 Max 档滑块离橙钮只有 94px；收到 40 |



## ChatGPT 聊天模式（CARD-06c 第 1/2 条）

聊天（chat）和工作（work）是两套东西，别混：

| | 模型 | 强度 | 最高档 |
|---|---|---|---|
| work | 9 项（gpt56_luna … gpt61_sol） | 五档 轻度/中/高/极高/Max | gpt61_sol + max |
| chat | 2 项（GPT-6 / GPT-5.6 Sol） | 三档 即时/中/高（instant/mid/high） | **gpt6 + high** |

- 档名跟着界面走：聊天模式最低档写「即时」，内部 key 是 `instant`（工作模式的「轻度」才是 `low`）。
- 读当前模式（chat/work）**先看 UIA 的 TogglePattern**：两个模式按钮都带这个模式，
  选中的那个 `ToggleState=1`、未选的是 0（2026-11-02 实测）。比"比两个词的墨色"稳——
  不受缩放影响，也不会被 Chrome 的标签页悬停预览卡片挡住（那张卡盖住页面左上角时，
  墨色判据在 work 模式下会整个读成 unknown）。墨色只作兜底，且**只在页头那一条**里找：
  侧栏第一个菜单项也叫「聊天」，全窗口找会把工作模式读成"两个词一样黑"。
- 芯片文字中英都认：`中/Medium`、`高/High`、`即时/Instant`、`极高/Extra High`。
- `--list` 一次读回两项：模型来自模型列表的 RadioButton 选中态，强度来自芯片文字。
- 回执里记 `writer=chat|work`，`use` 按 writer 去 `docs/tiers.json` 的 `writers.<模式>` 取白名单，
  不会拿工作表去比聊天档（那样会被 `purpose_mismatch` 拒发，06b 实测过）。
- 强度层里**找不到「选择模型」入口**时返回 `stage=no_model_selector` 并作废旧回执
  （readback 写 null），不沿用上一次的档位（CARD-06c 第 3 条）。
  注意：本机 2026-11-02 实测**工作模式是有这个入口的**（`选择模型` + `重置为默认` + `强度`），
  这条分支是为"入口被改版拿掉/没渲染"准备的 fail-closed 兜底，日常不会触发。

### 写入器模式（已做完，2026-10-29 12:40）

`chatgpt_choose.py --writer chat|work`、`gemini_choose.py --writer dialog|task`。
两者都实测往返：chat→work→chat、dialog→task→dialog，每次都有 before/after 复核。

**判据是逐像素差，不是模板相似度。** 这条是试出来的：

| 做法 | 结果 |
|---|---|
| 截白胶囊 | 白底白胶囊，几乎一片白，全屏到处能匹上 |
| 截"聊天/工作"文字 | 四种态互相都匹到 1.000，分不开 |
| 整组图 + 归一化相关 | 同态 1.000 / 异态 **0.980**，差太小 |
| **整组图 + 逐像素差** | 同态 **0.00** / 异态 **29.2**，干净 |

所以：`read_writer` 先用整组图定位那一块（阈值放到 0.62 只借位置），
再把整块和每张候选图做逐像素平均差，最小且 <12 才算认出来。

## 各端实测结论（都是踩出来的）

| 端 | 输入框锚点 | 发送键怎么判 | 动作条 | 坑 |
|---|---|---|---|---|
| deepseek | 麦克风图标 `ds_composer`，偏移 (-300,-65) | **颜色**：B-R>100 才可点 | `ds_actions` 6 连排 | 深蓝/浅蓝模板分都是 1.000 |
| grok | 「+」`grok_composer`，偏移 (250,-27) | **出现即用** | `grok_actions` 6 连排 | 占位文案轮播，不能当锚点 |
| chatgpt | 「+」`gpt_composer`，偏移 (240,-5) | **出现即用**（橙底换图标） | `gpt_actions` 6 连排 | 窗口标题会变成会话名 |
| gemini | 「+」`gem_composer`，偏移 (200,0) | **出现即用**（蓝色圆） | `gem_actions` 5 连排 | **复制在第 4 个**，不在排首 |

几条通用规律：

1. **发送键往往"空箱不出现"**：grok/chatgpt/gemini 空输入时右侧是语音键，
   输入后才换成发送键。所以"发送键出现"本身就是"文字写进去了"的判据。
2. **chatgpt 的橙色按钮换图标不换色**：波形→箭头，颜色一样，只能靠模板形状区分。
3. **chatgpt 的模型菜单点芯片开**（2026-11-02 CARD-06c 改正）：
   早先写的 `Ctrl+Shift+M` 会被 Chrome 截成个人资料菜单，弹层根本没开。
   现在从 UIA 取「选择 ChatGPT 模型」按钮的矩形、点它的中心：点前验唯一性和
   "不落在听写/语音/发送按钮里"、离橙钮 ≥60px，点后复核弹层真的出现。
   早期靠"橙钮 + 偏移"算芯片位置是对的教训——橙钮左边 **43px 就是麦克风**
   （-40 / -44 全中），所以**不要用偏移量算芯片坐标**，要用 UIA 给的矩形。
4. **不要用"参照物 + 固定偏移"去定位控件**。这是上面那个坑的根因。
   参照物自己在变（橙钮空箱是麦克风、有字是发送），偏移量就永远追不上；
   芯片文字长短也会变（「选择推理强度」比「GPT-6.1 Sol」宽一倍），左边界跟着动。
   参照物只能用来"取坐标"（比如用它圈定搜索范围），不能用来"算坐标"。
5. **弹层里的入口行不要用文字模板**。它写的是当前模型名，切一次就换一次字
   （「GPT-6.1 Terra」→「GPT-6 Sol」），模板必然失效——实测切到 GPT-6 Sol 后
   匹配分数掉到 0.71 以下，报"打不开模型列表"。
   改用几何：弹层里从上到下是 档位字 / 入口行 / 滑杆，取最上块的上边和最下块的下边
   的中点就是入口行高度，横向对齐档位字中心（注意最左边还挂着一个菱形图标，
   要按"最大间隙"切掉，否则中心会偏 35px）。
   判据用**非背景**（灰度<210）而不是橙色：档位字笔画细，橙色像素只有 40 来个，
   按橙色面积筛会把它滤掉。
6. **同一个控件不要循环重试**。为了"稳"加 retry，实际效果是半分钟里连点同一个位置十几次，
   既没解决定位问题，又会把额度/限流打出来。
7. **点击预算要按"一次完整操作"算**。一次 `--model` 要开两遍菜单（切前读、切后复核），
   如果读一次就开关一遍菜单，就会开三遍、点 7 下；预算设 8 时刚好撞穿，
   超了以后每一下都被拒，表现为"第一个失败、后面全报打不开"。
8. **橙色护盾只在橙钮附近生效**。全屏查橙色会把弹层里橙色的档位字也算进去，
   入口行就在它下面 2px，实测被拦（"12px 内有 102 个橙色像素"）。半径取 100px：
   麦克风最危险时距离是 43px，够覆盖，又放得开入口行（131px）。
9. **标题会变成会话名**：ChatGPT 开个会话后窗口标题成了「回复收到」。
   所以 `bring_to_front` 对网页端一律按 **"Google Chrome" + 中心在副屏** 找，
   不按站点名找。

## 复制键：整排定位（用户提的判据）

回答下面的动作条是整排图标，全屏唯一；提问气泡上的复制键是孤立的。

## 你正在用电脑时，脚本不抢（2026-10-29 13:50）

脚本第一步就是 `bring_to_front`——把浏览器提到前台，这本身就会抢焦点，你在打字就会丢字。
所以在**一切动作之前**加了一道闸：

- 用 `GetLastInputInfo` 读系统最后一次键鼠输入时间。
- 默认要求**连续 2 秒没输入**才开跑；不满足就等，最多等 120 秒，等不到就退出（退出码 4），不硬抢。
- `--idle N` 改"要空闲几秒"，`--wait N` 改"最多等多久"，`--force` 跳过检查。
- **运行中**再查一次：真正点"发送"之前，如果检测到你 0.6 秒内动过键鼠，直接中止并返回
  `user_took_over`，不点发送。

四个 `_use`、四个 `_choose` 全部接入（`src/qi/guard.py`），包括 deepseek/chatgpt/gemini
这三个不走通用 CLI 的独立脚本。

```bash
# 你正在用电脑：它会等，等不到就退出
python src/scripts/grok_choose.py --list --tab 1

# 明确允许它现在就跑
python src/scripts/grok_choose.py --list --tab 1 --force
```
