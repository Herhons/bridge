# Round 1 会审提问

你是独立的代码/流程评审者。附件 `material.md` 含三部分：**规格全文**、**代码库现状**、**已知真机问题**。
请**只依据附件**评审，不要去仓库或网络找文件（附件就是全部材料）。

## 输出格式（硬要求，验真会逐条核对）

首行只写一行：`可访问=是`（读得到附件）或 `可访问=否`（读不到，后面可停止）。

然后给 **6 条意见**，按「对本项目的好处」从高到低排序。每条严格按下面五段写：

```
§章节号 或 文件路径:行号
「从附件里逐字抄出的一句原文（连续、不改写、不省略）」
问题：为什么这是问题
失败：会在什么情况下失败、失败时看到什么
改：具体怎么改（能落到文件/函数就写出来）
验收：没有真机时，用什么离线测试能证明改好了
```

- 引用必须是**附件里真实存在的连续文字**，用「」括起来；不要用「」给自己的话加引号。
- 章节号只说明位置，**不代替引句**；一条里至少一句引句。
- 不要复述提问，不要泛泛而谈。总长 2500 字以内。

## 本轮必须回答的五个方向（Herhons 指定）

1. **稳定优先**：当前这套「屏幕坐标点击 + 全局按键」最容易在哪儿炸？给出让它不可能误伤桌面/其他窗口的结构性做法（不是再加一个 if）。
2. **精简代码**：目标是「一个总控脚本 + 各家 AI 的 use/choose 模块」。请给出**具体架构**：模块边界、统一接口、四端各自保留什么、迁移顺序、如何避免再长出第二套发送栈。
3. **会话回归**：怎么可靠判断「当前是否还在本轮那个对话」，不在时怎么找回去（而不是新开一个）。
4. **重复点击与拿不到回复就新开对话**：定位这类问题的共同根因，给出一次性收口的改法。
5. **推进器分工（西西弗斯）**：以后的循环按「Gemini 汇总产出的计划」推进，
   西西弗斯只负责**交接与续跑**（把计划交给施工方、崩溃后接着跑），不自己做决定。
   请评这个分工是否合理：职责边界、状态该存在哪、什么情况下它必须停下来交人。

可以合并方向（例如第 3、4 条合并成一条），但**总共仍要 6 条**。
