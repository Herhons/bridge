1) 主题聚类与合并说明聚类一：UI 焦点与输入防误触硬闸门（合并 F1-A、F2-1）
将裸屏幕坐标点击降级为最后手段，收口至统一的 safe_input / safe_ui_action 原语。硬拦桌面及任务栏黑名单类名（Progman、WorkerW、Shell_TrayWnd）；点击前校验坐标严格落在目标 GetClientRect(hwnd) 内且 WindowFromPoint 归属目标进程树；发送 Ctrl+A/Delete 等破坏性按键前，双重校验 GetForegroundWindow() == hwnd 且 UIA GetFocusedElement() 为可编辑区（Edit/Document），发键前后二次核对，异常即中止并释放 ui.lock。聚类二：幂等状态探针与四阶段提交账本（合并 F1-D、F2-2）
用 ensure_state(target) 替代盲目重放动作序列，菜单等 toggle 控件先探测展开态再动作。账本状态细化为 staged（已填草稿）→ dispatched（已点发送）→ accepted（观测到输入框清空且消息流出现本轮 prompt 指纹或停止生成按钮）→ completed。ask 超时后若已 accepted 则仅在原会话 poll_reply_only，严禁盲目 start_new_chat；若停在 staged/dispatched 且文字仍在，仅补点发送。聚类三：会话锚点与漂移自愈（合并 F1-C、F2-3）
引入 SessionAnchor(site, round_id, expected_url, prompt_hash, is_new)。每次操作前核对当前 URL 与页面末条消息摘要是否匹配锚点；漂移时优先按账本 expected_url 跳转并核对 prompt_hash，URL 失效则在左侧历史栏按首句关键词/标题匹配找回；仅在找回失败且本轮未 accepted 时允许导航至根路径新建会话，并在账本标记 new_session=true 拦截重复新建。聚类四：统一总控与无状态端插件架构（合并 F1-B、F2-4）
将 20 个脚本与 qi/ 下 39 个模块的并行发送栈收敛为「1 个总控 + 各端 SiteAdapter/SiteDriver 插件」。总控层独占 UI 锁、焦点闸门、账本状态机、剪贴板保护与超时轮询；各端驱动仅实现无状态选择器与原子动作（choose_model、ensure_session、clear_composer、upload_file、paste_chunk、submit、read_reply），原有 *_use.py / *_choose.py 退化为 CLI 薄壳。聚类五：推进器职责边界与独立核实闸门（合并 F1-E、F2-5）
汇总端仅产出「聚类+优先级建议」，无权直接作为施工计划。推进器保持纯确定性状态机（按 plan.md 条目 ID 断点续跑），在汇总与施工之间强制经过非施工方席位的逐条源码核实，生成带精确 文件:行号 的 verification.md 与 plan.md，并通过脚本校验未触碰硬停红线后方可交接施工。聚类六：上传模式与材料形态解耦的引用验真（单列 F2-6）quote_check.py 验真规则不再与传输方式（upload/paste）硬绑定，而是与「材料内容形态」绑定。上传带行号源码包时校验 文件:行号；上传 material.md 等汇总文档时，支持「章节号/文件:行号 + 逐字引句」双轨验真，避免诚实不编造行号的回复被误判为未读而触发凑不够 3 家的假性停机。2) 冲突标注会话漂移且 URL 恢复失败时的兜底策略冲突（F1-C vs F2-3）：F1-C 允许在历史列表找回失败后新建会话（账本标记 new_session=true 并禁止同提问重试新建）；F2-3 要求若本轮已 accepted 而 URL 失效且无锚点时直接报错停机，仅在尚未 accepted 时允许重置到根 URL 新建。建议采纳 F2-3（按是否已 accepted 区分），防止已发送任务在找回失败时重开会话导致重复提问。重构迁移顺序冲突（F1-B vs F2-4）：F1-B 主张先抽接口并对四端现有实现做薄封装、跑通录制回放夹具后再逐端替换内部实现；F2-4 主张先在 qi/ 抽好统一发送栈基类，按「四审网页端 → 施工与验收桌面端」分批直接迁移并将原脚本退化为 15 行 CLI 薄壳。核实环实现机制冲突（F1-E vs F2-5）：F1-E 侧重推进器消费核实表判定来过滤汇总项；F2-5 明确要求推进器纯确定性化（绝不内嵌 LLM 拍板），必须增设独立的非施工方模型席位生成 verification.md 与 plan.md。3) 按对本项目的好处排序聚类一（UI 焦点与输入防误触硬闸门）：最高优。直接阻断打偏窗口、误删桌面图标及切走直播窗口的破坏性真机事故，守住 §1 安全红线。聚类二（幂等状态探针与四阶段提交账本）：直接消灭 toggle 菜单死循环、超时重开会话导致的双份提问，以及假阳性 accepted 造成的账本死锁，大幅提升单轮无人值守成功率。聚类三（会话锚点与漂移自愈）：解决多轮会审与中断续跑时的上下文串台、新轮次污染旧会话及收卷读空问题。聚类五（推进器职责边界与独立核实闸门）：在「核实通过即施工」的无人值守模式下，防止会审扩大化的假问题或施工模型自审自批直接改坏代码库。聚类六（上传模式与材料形态解耦的引用验真）：修复单文件打包上传时的验真规则断层，消除因全员不编造源码行号而导致的假性停机。聚类四（统一总控与无状态端插件架构）：消除 39 个模块的并行发送栈，根治「修一处漏三处」的维护泥潭，为前序机制提供单一收口点。4) 汇总者新增剪贴板事务锁与脏数据隔离（关联 F2-4 剪贴板保护）：多段 paste_chunk 期间若用户在宿主机发生复制操作，或发送栈异常中断，极易将外部剪贴板内容贴入 AI 输入框或污染用户剪贴板。应在总控发键原语中增加剪贴板快照恢复与写入后即时校验（写剪贴板 → 焦点硬闸门 → Ctrl+V 前再次核对剪贴板 SHA 与当前分片一致），不一致则中止粘贴并告警。F1 尾部提示词回显残留：F1 文本末尾混入了 3 段不同轮次的原始 Prompt 指令文本，说明收卷提取或匿名打包脚本在截取模型回复边界时未干净剥离系统提示词回显（或模型复述了尾部指令），需在收卷清洗与 quote_check.py 分母计算中过滤此类回显块，避免拉低引用命中率。
