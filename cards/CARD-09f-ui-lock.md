现象：16:52–16:54 我在跑 grok_use（会审 CARD-10），同时 WorkBuddy 施工 09e 时自己跑了 evidence\card09e_probe_uia.py / card09e_probe_writer.py（16:52:23–16:53:39 驱动 Gemini 标签页）和 chatgpt 试跑（16:53:58 fail 截图）。同一 Chrome 窗口 hwnd=526630 被来回切标签，grok_use 一次 input_mismatch（发送到一半被切走）、一次 interrupted（目标文档变成 Gemini）、一次 draft_present（半截草稿残留）。根因：ui.lock 不是全程持有，且临时探针脚本根本不拿锁。

1. 所有 *_choose / *_use / 探针脚本：从启动到读完回复（或失败退出）全程持有 runs\ui.lock（跨进程文件锁，含 pid+启动时间，死锁持有者自动回收）；拿不到锁就等待并打印持有者，超时退出独立码。
2. 提供 qi.uilock.hold() 上下文管理器，evidence\ 与 tools\ 下的临时探针也必须用；施工方写真机探针前先拿锁（写进卡模板和 PLAN 规则）。
3. use 发送阶段检测到前台标签/文档被换走：立即停止输入，清空本次已写入的半截文本并读回为空，再以 concurrent_ui 失败退出，不留草稿。
4. 单测：两个进程抢锁只有一个进入；持有者死亡后可回收；发送中途文档变化 → 清草稿 + 退出码。
规则（PLAN）：会审各席严格串行，上一席发出并读完回复后才开下一席；施工卡运行期间主线不跑真机席位，或双方都经锁。
允许改：src\qi 锁模块、各 *_choose/_use、tools、tests、CHANGES、progress.json 本卡字段。禁止同 09e。
